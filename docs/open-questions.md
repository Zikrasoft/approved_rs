Копятся по ходу работы над разделением портфеля на независимые бренды.
Стратегические вопросы — в плане (`~/.claude/plans/encapsulated-whistling-melody.md`),
здесь только то, что всплыло при реализации и требует решения владельца/клиента.

## Блокирующие

_Пусто — ничего не блокирует текущую фазу._

## Требуют решения до фазы 3 (детейлинг)

### 1. Имена и домены двух новых брендов

`CarLabDetailing.rs` / `CarLabAutoservice.rs` названы заглушками. Нужны
финальные. Правило из плана: **общего корня бренда быть не должно** — пара с
общим корнем читается как один бизнес с двумя вывесками и обнуляет смысл
разделения. Также избегать семантики Approved (доверие / проверка / certified /
verified / trusted).

Без этого нельзя завести `apps/detailing` и `apps/auto-service` с осмысленными
именами пакетов и конфигами сайта.

### 2. Дизайн-скилл для детейлинга

В плане зафиксировано «премиальный сайт», конкретный скилл выбирается перед
фазой 3. Кандидаты: `imagegen-frontend-web` → `image-to-code` (генерит
референс-картинку на каждую секцию, потом верстает по ним),
`high-end-visual-design`, `design-taste-frontend`.

## Требуют решения до фазы 4 (автосервис)

### 3. Ставки реферальной комиссии по бизнесам

Нужны конкретные проценты для дефолтов в конфиге каждого приложения.
Из разговора: автоподбор ~10%, детейлинг ~50%. Автосервис — неизвестно.
Переопределение на уровне заявки будет в любом случае, вопрос только про
дефолты.

### 4. Источник данных совместимости аккумуляторов

Фильтр «подбери аккумулятор под мою машину» (марка / модель / год →
типоразмер / ёмкость / полярность). Варианты: ручной каталог под ходовые
модели сербского рынка, внешняя база (TecDoc и аналоги, платная лицензия),
или простой фильтр по параметрам без привязки к автомобилю.

Отдельный технический риск: в staywildwear фильтры каталога чисто клиентские —
все карточки рендерятся в HTML, JS их прячет. Для фитмента это не
масштабируется, понадобится серверный запрос или предсобранный индекс.

### 5. Хостинг Medusa-бэкенда

Решено: фронты на Vercel, Medusa отдельно (managed — Railway / Render / Fly,
либо Hetzner VPS). Конкретный провайдер не выбран.

### 6. Полный список услуг автосервиса

Нужен для структуры сайта: механика, ДТП-восстановление, покраска кузова,
магазин — что ещё, и как это группируется в навигации.

## Технические, решаются без владельца

### 7. `packages/ui-kit` отложен до фазы 3

`BaseCustomElement` и базовый Tailwind-пресет выносить сейчас некуда —
приложение одно, а approved.rs на React (Keystatic на нём завязан) и своих
custom elements не использует. Пакет появится вместе с первым сайтом, который
им реально пользуется, чтобы граница пакета рисовалась по двум реальным
потребителям, а не по одному предполагаемому.

### 8. Метка бренда в сообщениях бота — отложена до второго бренда

План требует, чтобы при одном общем Telegram-боте на три бизнеса в сообщении
была явная метка бренда, иначе непонятно, откуда лид. Пока приложение одно,
метка была бы шумом в каждом сообщении — не реализована. Добавляется вместе с
`apps/detailing`, тогда же станет видно, где именно она нужна (тизер в группе,
карточка в личке, или обе).

Ключ хранилища уже разведён по бизнесам (`storage: createVercelBlobStorage({
path })`), так что лиды разных брендов не смешиваются с самого начала.

### 9. Базовый `tsconfig` в корне

Сейчас не выносился: `astro/tsconfigs/strict` уже даёт весь строгий набор, а
`paths` резолвятся относительно своего файла и из корня указывали бы не туда.
Выносится вместе со вторым приложением, когда станет видно реальное общее.

## Отвеченные

### `vercel deploy` из монорепо — не проверен локально

Требует прод-креденшелов. Джоба `deploy` переведена на
`working-directory: apps/approved-rs`, потому что Vercel CLI определяет проект
по рабочей директории. Проверится на первом деплое с `main`.
