# A BMW type code reaches crawled Vehicles through open type-key data and staff links

Decided 2026-10-28 with the owner for [#427](https://github.com/Zikrasoft/approved_rs/issues/427). Completes the BMW half [ADR-0050](0050-a-vin-reaches-crawled-vehicles-through-the-baumuster-their-models-list.md) left open.

**Decision:** a BMW VIN decodes to its type code (characters 4 to 7), and the code reaches Vehicles in this order. First the Vehicles staff linked the code to: a VehicleIdentifier of type `bmw-type-code`. One code may now be linked to several Vehicles (the unique index is per type, value and Vehicle), because one type code often covers what the crawl splits into several Vehicles. Staff link a code from the Unresolved VINs screen, which lists each code customers searched for with its lookup count, when it was last searched and what the open data calls it, so real customer VINs fill the table over time. Only when no staff link exists, the code is looked up in a committed copy of the BimmerArchive type-key table (`apps/auto-service-shop/src/lib/vin/bimmerarchive-type-keys.json`) and its row is matched against the crawled Vehicles of the decoded Make on facts: the chassis code must be one the Vehicle's Chassis lists, the engine family and the power in kW must be equal, and a fact both sides state must not disagree (displacement within 0.1 l, the model number, the body a crawled name gives, the drive a crawled name or the Vehicle gives, the steering side, and the production years). Where the crawl names an xDrive Vehicle apart from a plain one, an all-wheel-drive code keeps only the xDrive one. The row's steering side becomes the lookup's `facts.steering`. As in ADR-0050, exactly one Vehicle resolves the VIN; several are never narrowed by guessing: the lookup stays unresolved and names them as `vehicle_ids`, with `model_slug` when they share one Model. A VinLookup's stored Vehicle is no longer answered from the record: every lookup matches again, so a link staff add or an Import that adds a Vehicle changes the answer at once. The decoders are local, so a rematch costs a few queries.

**Provenance and licence:** the table is `data/production-codes.csv` of [alisacorporation/bimmerarchive-open-data](https://github.com/alisacorporation/bimmerarchive-open-data) at commit `58b012a2a5531f9572b86bcc4b4f86b197da3323` (2026-09-19), itself rebuilt from Wayback Machine snapshots of the defunct bimmerarchive.org (snapshot timestamps in that repository's `api/v1/meta.json`). Only the 4,020 BMW rows are kept (MINI and Rolls-Royce dropped), with the columns `code, chassis, model, body, engine, power_kw, drivetrain, steering, from, to`, converted to JSON without correcting or filling anything. The repository's code is MIT; its `DATA.md` calls the rows uncopyrightable facts and says to use them freely, credits the original compilers, offers takedown on request, and leaves open whether the EU _sui generis_ database right (Directive 96/9/EC) applies; GitHub reports the licence as `NOASSERTION`. `docs/research/vin-decode-cheap-alternatives.md` recommended seeding only pilot rows to stay away from substantial extraction; the owner chose the whole BMW set. If a rights holder objects, deleting the JSON file and its import leaves staff links working on their own. This is not legal advice.

**Coverage on the #422 Import** (local, 759 crawled BMW Vehicles, none with a type code): 1,493 of the 4,020 codes resolve to exactly one Vehicle, 91 name several Vehicles of one Model and 46 several Models; 269 Vehicles are reached by at least one resolving code and 312 by any. The data has no G20/G21 rows and few G-series chassis, so `35BG` and most current cars still need a staff link.

## Considered Options

- **Write the open-data match back as VehicleIdentifiers at Import.** Rejected: the match is a deduction from facts, and storing it would make it indistinguishable from a code staff confirmed, which is what lets a staff link win.
- **Seed the table into Postgres.** Rejected for now: the rows are fixed at a pinned commit and read-only, so a committed file needs no migration, no seed step per environment and no admin screen.
- **Require an xDrive VIN to match only a Vehicle named xDrive.** Rejected: most crawled names carry no drive at all, and the rule dropped 31 resolved Vehicles on #422; narrowing applies only where the crawl itself names the xDrive Vehicle apart.
