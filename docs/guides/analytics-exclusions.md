# Исключения из аналитики Yandex Metrika

Кого выкидывать из любой выборки, прежде чем делать выводы по трафику и
конверсии. Применять ко всем трём счётчикам — их id перечислены в
[deploy.md](deploy.md).

Словарь событий и целей — в [analytics.md](analytics.md).

## clientID владельцев и партнёра

Сам список — в `.local/analytics-exclusions.txt`, он в `.gitignore`. Это
идентификаторы браузеров конкретных людей, а репозиторий публичный: clientID
равен значению cookie `_ym_uid`, которую читает любой скрипт на своём домене,
так что опубликованный список превращает обычную XSS в прицельную по владельцу.
Формат файла — по одному id в строке.

Масштаб, ради которого фильтр нужен: на approved.rs за 31.08–22.09.2026 эти
браузеры дали 105 визитов из 273 и 6 из 14 отправок формы. Без фильтра
конверсия завышена примерно вдвое.

## Россия

Регион `Russia` исключается целиком: клиентов оттуда нет, это заходы своих и
случайный трафик. За тот же период — ещё 9 визитов.

## Как применять

В Reporting API `clientID` нет ни как измерения, ни как фильтра — только
`ym:s:clientID` в Logs API. Поэтому выборка с исключениями строится так:

1. `logs_request` с `source: "visits"` и полями `ym:s:clientID`,
   `ym:s:regionCountry`, `ym:s:goalsID`, `ym:s:date`, `ym:s:startURL`,
   `ym:s:pageViews`, `ym:s:visitDuration`, `ym:s:bounce`
2. скачать, отфильтровать локально по `.local/analytics-exclusions.txt` и по
   стране, агрегировать
3. `logs_clean`, чтобы освободить квоту счётчика

Страна в логах приходит строкой (`Russia`, `Serbia`), не числовым id региона.

## Что уже стоит в самой Метрике

На всех трёх счётчиках активен фильтр `exclude uniq_id me` — «не учитывать мои
визиты». Он работает по cookie браузера и накрывает только те браузеры, из
которых открывали отчёты счётчика, поэтому телефоны и браузеры партнёра в него
не попадают. Фильтра по clientID в интерфейсе Метрики не существует.
